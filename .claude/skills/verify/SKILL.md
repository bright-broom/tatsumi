# verify

変更が壊していないことを、実際にコマンドを走らせて確認する。「たぶん大丈夫」で終わらせない。

## 手順

1. `git status` で差分が意図したものだけか確認する（`dev.log`、`.next`、`node_modules` が混ざっていないこと）。
2. `npm run verify` を実行する（typecheck → lint → 画像寸法チェック → build）。
   - 失敗したら原因を特定して直す。チェックを外して通さない。
   - フォント取得（Google Fonts）でネットワークエラーなら、コードの問題ではなく環境の問題として報告する。
3. `npm run smoke` を実行する（`build` 済みであること）。34 項目すべて `ok` になること。
4. 見た目・HTML・色・フォーム・メニューを変えた場合は `npm run a11y` も実行する（axe の違反 0 件が条件。Chromium が要る）。
5. build の出力を確認する。
   - ルート一覧が `/`, `/news`, `/privacy` = ○（静的）、`/api/contact` = ƒ（動的）であること。
   - ビルド警告は 0 件が基準。**警告が出たら直す。**
6. UI に関わる変更は、実際に表示して確認する（`npm run dev` を起動して該当セクションを見る）。

## 補足

- lint は警告 0 件が条件（`--max-warnings 0`）。ルールを無効化して通さず、コードを直す。

## 報告の形式

- 何を実行し、何が通ったか（コマンドと結果）
- 新規の警告・失敗とその原因
- 実行できなかった確認（あれば理由つきで）
